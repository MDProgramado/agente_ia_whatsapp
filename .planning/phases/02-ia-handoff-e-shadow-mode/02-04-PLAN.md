## Decisão de sinal (CR-01) — registrada aqui para não ser re-litigada

O review sugeria reduzir o predicado a `fromMe === true` puro (invariante de socket único). A instrução de gap-closure exige que "um fromMe de outro número NÃO marque" — logo o predicado mantém a CHECAGEM DE IDENTIDADE DO CANAL, mas sobre o EMISSOR correto:

- `EventoInbound` ganha `senderPhoneE164?: string | null` — E.164 do EMISSOR da mensagem.
- `criarEventoInbound(m, canalSelfJid?)`: `fromMe === true` → emissor é o socket próprio → `normalizeJid(canalSelfJid ?? "").e164`; `fromMe` falso → emissor é o par → `normalizeJid(chatId).e164`.
- `criarHandlersDoCanal` ganha `canalSelfJid?: () => string | undefined` (getter, porque `sock.user` só existe após o registro); o boot (`src/index.ts`) passa `() => sock.user?.id`.
- `deveMarcarPrimeiroContatoHumano({fromMe, senderPhoneE164, channelPhoneE164})`: `fromMe === true` E `senderPhoneE164 != null` E `senderPhoneE164 === channelPhoneE164`.
- Edge aceito: se `sock.user.id` vier em forma LID (`@lid`), `normalizeJid` devolve `e164: null` → predicado falso (fail-closed, R-001) com warn — revisitado no pareamento real (P-004). Comparar `remoteJid` contra E.164 continua PROIBIDO.
